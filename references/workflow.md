# 实拍要求 + 深度估计工具链

## 实拍要求（第 3 步）

原则：**深度只吃结构不吃画质，但结构必须对。**

| 维度 | 要求 |
|---|---|
| 设备 | 手机即可；广角/标准焦段都行，鱼眼畸变大的避开 |
| 站位 | 人物/物体站位必须与目标一致——这是最贵的一步，站位错了后面全错 |
| 运动 | 走位、比划动作、找人站个位；运镜轨迹与目标一致（要手持就手持，要推拉就推拉） |
| 时长 | 覆盖目标镜头完整时长，宁长勿短（后续可裁区间） |
| 帧率 | ≥ 24fps；深度序列帧间运动过大会估计不稳 |
| 画质 | 允许糙：噪点、轻微过曝、压缩痕迹都不影响；但**运动模糊要可控** |
| 环境 | 光照均匀最好；顺光/侧光优于逆光（逆光下轮廓丢失→深度估计退化） |

## 深度估计工具链（第 4 步）

按平台能力三选一，优先用生成平台内置的（链路最短）：

| 层级 | 工具 | 适用 |
|---|---|---|
| 平台内置 | 生成平台自带深度控制节点 / depth 参考图字段 | 首选——深度直接进生成，无中间格式损耗 |
| 中间件 | ControlNet Depth（Stable Diffusion 系）、Depth Anything V2、MiDaS、ZoeDepth | 平台无内置节点时，导出灰度深度序列再喂入 |
| 后期 | 逐帧抽深度 → 灰度视频（MP4/ProRes，8-bit 够用） | 需要跨平台流转或人工微调深度图时 |

### 深度序列验收标准（枢纽步骤，不验收后面全错）

1. **结构正确**：抽 3-5 帧目检——前景/中景/后景层次与实拍一致，人物轮廓清晰可分
2. **时序连续**：播放深度视频无跳变/闪烁；运镜方向与实拍一致
3. **崩点扫描**：按 gotchas.md 四类崩点逐帧过一遍，命中帧标记出来（该区间弃用或回炉）
4. **运动可辨**：深度序列里能直接看出推拉摇移/手持抖动——看不出运动=深度序列没承载运动信息，重估

验收不过就回 3（重拍）或换估计工具，不带病进生成。
